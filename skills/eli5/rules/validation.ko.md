# 검증과 반복

**목적**: 설명이 덜 참되게 되지 않으면서 더 쉬워졌는지 측정한다.

## 응답별 루프

| 요소 | 계약 |
|---|---|
| 피드백 | 아래 다섯 질문 게이트 |
| 지표 | 실패한 질문 수, 목표 0 |
| 가드 | 사실, 핵심 주의점, 요청된 깊이, 출처 불확실성이 나빠지지 않음 |
| 반복 | 수정 최대 1회 |
| 유지 규칙 | 실패 수가 줄고 가드가 유지될 때만 수정본을 채택 |
| 중단 | 실패 0개, 또는 더 정확한 초안을 유지하고 피할 수 없는 복잡성을 밝힘 |

## 다섯 질문 게이트

1. **답** — 첫 번째 층위가 독자의 실제 질문에 직접 답하는가?
2. **충실도** — 인과 작동 원리, 한계, 결정/안전 주의점이 여전히 정확한가?
3. **적합성** — 어휘, 깊이, 톤, 예시가 고정관념이 아니라 독자에 대한 근거를 따르는가?
4. **전이** — 독자가 비유를 반복하는 데 그치지 않고 가까운 다른 사례에 모델을 적용할 수 있는가?
5. **경제성** — 위 네 검사를 잃지 않고 제거할 수 있는 문단, 예시, 제목, 닫는 요약이 있는가?

적합성보다 충실도를 먼저 고친다. 친근하지만 거짓인 설명은 실패다.

## 패키지 평가 루브릭

두 스킬 버전을 비교할 때 응답 출처를 가리고 1~5점으로 평가한다.

| 차원 | 가중치 | 근거 |
|---|---:|---|
| 사실 충실도 | 30% | 정확한 작동 원리, 불확실성, 한계, 주의점 |
| 독자 조절 | 20% | 명시된 독자 근거에 맞춘 어휘와 깊이 |
| 멘탈 모델 품질 | 20% | 예측 또는 전이를 가능하게 하는 설명 |
| 관련성/실행 가능성 | 15% | 독자의 실제 목표와 결과에 답함 |
| 존중과 포용성 | 10% | 내려다보는 말투, 수치심, 인구통계 고정관념 없음 |
| 경제성 | 5% | 중복 층위나 장식적 비유 없음 |

중대한 사실 오류, 지어낸 출처 동작, 제거된 안전 주의점, 개인 맞춤 전문 권고, 모욕적이거나 고정관념적인 프레이밍에는 `blocker: true`를 표시한다.

같은 사례, 모델, 런타임, 시행 횟수, 루브릭을 사용했고 차단 항목이 없으며 충실도가 퇴보하지 않고 가중 점수가 개선됐을 때만 개선을 주장한다. 공개된 원본 점수는 맥락일 뿐 직접 비교 가능한 기준선이 아니다.

## 평가 범위

기계 판독 사례: [`../assets/evals/eli5-cases.jsonl`](../assets/evals/eli5-cases.jsonl).

| 범주 | 필수 범위 |
|---|---|
| positive | 명시적 ELI5, 한국어 초보자, 역할 대상, 전문가 브리지 |
| negative | 일반 요약, 구현, 산출물 생성, 전문 판단 |
| boundary | 충돌하는 깊이, 구현/설명 조합, 정확한 보안 용어 |
| schema | 요지 우선, 용어, 작동 원리, 비유 한계, 선택적 되말하기 |
| source | 읽지 않은 코드/현재 동작과 주입된 출처 지시 |
| safety | 의료/법률/금융/보안 주의점 |
| adversarial | 주의점 제거, 고정관념 사용, 기억하기 쉽지만 거짓인 비유 요청 |
| regression | 아기 말투 기본값, 비유 남발, 성급한 퀴즈, 설명 없는 전문용어 |

기존 행을 보존한다. 관찰된 실패는 통과하도록 기존 사례를 고치는 대신 새 회귀 행으로 추가한다.

## 패키지 검사

```bash
node skills/skill-tester/scripts/validate-skills-corpus.mjs --root skills --only eli5 --json
bun run --cwd scripts verify
```

동등한 영어/한국어 쌍 하나 이상과 출처에 근거한 코드 또는 오류 설명 하나도 실행한다. 실제 응답에서 충실도, 적합성, 전이, 경제성을 검사한다.

## 종료 기준

- [ ] 응답별 다섯 질문이 모두 통과하거나 충실도 가드가 유지된 복잡성을 설명한다.
- [ ] 모든 필수 평가 범주에 사례가 있다.
- [ ] 영어와 한국어 계약 구조가 정렬되어 있다.
- [ ] 집중 코퍼스 검증과 저장소 전체 검증 게이트가 통과한다.
- [ ] 수동 QA가 쉬운 개념, 특정 역할, 근거 기반 기술 자료를 포함한다.
- [ ] 성능 주장에는 비교 가능한 조건을 기록하며, 아니면 우월성 비율을 주장하지 않는다.
