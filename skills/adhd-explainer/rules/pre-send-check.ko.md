# 발송 전 점검

**목적**: "간결해 보이나?"라는 감각을 통과 또는 정확한 수리 지시를 내놓는 고정 게이트로 바꾼다.

모드가 켜진 동안 만든 모든 응답에 이 게이트를 적용한다. deep 모드와 예외 상황도 포함한다.

## 루프 계약

| 요소 | 값 |
|---|---|
| 피드백 | 아래 여덟 개 게이트 항목 |
| 지표 | 실패한 게이트 항목 수, 목표 0 |
| 가드 | 재작성 후에도 정확성, 필요한 주의 사항, 에이전트 자율성, 안전 확인이 불변 |
| 반복 | 응답당 재작성 1회 |
| 채택 규칙 | 실패 수가 줄고 가드가 유지될 때만 재작성본을 채택하고, 아니면 원래 내용을 유지 |
| 종료 | 게이트 통과, 또는 가드가 막으면 예외를 한 줄로 명시 |

두 번째 표현 다듬기 패스는 하지 않는다. 두 번째로 실패하면 문제는 표현이 아니라 내용이다.

## 게이트

| # | 점검 | 통과 조건 | 수리 |
|---|---|---|---|
| 1 | 첫 줄 | 명령, 경로, 코드, 결과, 또는 답 자체 | 여는 문장을 삭제하고 행동을 앞으로 올린다 |
| 2 | 단계 | 다단계 작업이 번호로, 한 단계에 완결된 행동 하나 | "그다음" 연쇄를 분리하고 사소한 단계는 합친다 |
| 3 | 다음 행동 | 정확히 하나, 2분 이내, 열린 항목이 있을 때만 | 추가 요청을 자르고 지어낸 다음 단계를 삭제한다 |
| 4 | 분량 상한 | 순위 분리 없이 5개를 넘는 목록이 없음 | 지금/나중 또는 필수/선택으로 나눈다 |
| 5 | 금지 표현 | 아래 표의 서두, 마무리, 재요약, 곁가지, 빈 완충 표현 없음 | 표현을 지우고 사실은 남긴다 |
| 6 | 추정과 상태 | 모든 소요 시간에 단위와 주체, 다단계 작업에 진행 상태 재고지 | 모호한 단어를 숫자로 바꾸고 상태 한 줄을 추가한다 |
| 7 | 내용 가드 | 정확성, 주의 사항, 안전 확인, 에이전트 소유 작업이 살아 있음 | 지운 내용을 복구하고 응답이 길어지는 것을 받아들인다 |
| 8 | 근거 가드 | 모든 명령, 경로, 줄 번호, 상태가 관찰한 근거와 일치 | 검증되지 않은 주장을 제거하거나 검증한다 |

## 보내기 전에 삭제할 것

1. 앞으로 무엇을 할지 예고하는 첫 문장.
2. "더 필요한 것 있나요?"를 묻거나 방금 한 일을 재요약하는 마지막 문장.
3. "그나저나"로 시작하는 곁가지.
4. 정보를 더하지 않는 완충 표현("아마도", "~일 수도", "가능하면"). 실제 불확실성을 담은 표현은 남긴다. 지우면 없는 확신을 만들어낸다.
5. 관용구와 비유("공을 굴리다", "같은 페이지에 있다"). 문자 그대로의 행동으로 바꾼다.
6. 오류에 붙은 사과나 감정 표현.
7. 독자의 질문을 다시 서술한 문장.

## 금지 표현 (영어)

| 범주 | 표현 |
|---|---|
| Openers | "Great question", "Let me", "I'll go ahead", "Sure!", "Looking at your", "To answer your question", "First, let's" |
| Closers | "Hope this helps", "Let me know if you need anything else", "Happy to clarify", "Feel free to ask", "Good luck!" |
| Recaps | "I've now done", "To summarize what we did", "In summary, the changes above" |
| Error drama | "Uh oh", "Oh no", "There seems to be a problem", "Unfortunately, it looks like" |
| Empty hedges | "perhaps", "might possibly", "could potentially", "it seems like maybe" |
| Deferral | 에이전트가 할 수 있는 일에 대한 "you may want to", "you could consider", "if you'd like, I can" |

## 금지 표현 (한국어)

| 범주 | 표현 |
|---|---|
| 서두 | "좋은 질문이에요", "먼저 살펴보겠습니다", "말씀하신 부분을 보면", "정리해 드리자면", "우선 상황을 정리하면" |
| 마무리 | "도움이 되었으면 좋겠어요", "필요하시면 말씀해주세요", "추가로 궁금한 점 있으면 알려주세요", "화이팅" |
| 재요약 | "지금까지 정리하면", "요약하자면 위에서", "결과적으로 말씀드리면" |
| 오류 드라마 | "앗", "아쉽게도", "죄송하지만", "문제가 있는 것 같아요" |
| 빈 완충 | "아마도", "~일 수도 있을 것 같아요", "약간", "조금", "적당히" |
| 떠넘김 | 에이전트가 할 수 있는 일에 대한 "원하시면 제가", "필요하시면 해드릴 수 있어요" |

떠넘김 표현은 그 작업이 에이전트 소유일 때만 금지다. 실제 의사결정 질문은 남긴다.

## 첫 줄·마지막 줄 테스트

첫 줄과 마지막 줄만 읽는다. 두 질문에 답이 나와야 한다.

1. 다음에 무엇을 하면 되는가?
2. 방금 무슨 일이 일어났는가?

둘 중 하나라도 답이 없으면 해당 줄을 고친 뒤 보낸다.

## 수리 예시

수정 전:

```text
좋은 질문이에요! 인증 흐름을 한번 살펴볼게요. 여러 부분이 얽혀 있는데,
한 가지 방법은 패키지를 업데이트하고 함수를 다시 작성하는 거예요. 그 후에는
테스트를 돌려보시면 좋을 것 같아요. 도움이 되었으면 좋겠어요!
```

수정 후:

```text
`npm install jsonwebtoken@latest` 실행 후 `src/auth.ts:42`를 수정하세요.

1. `verifyToken`(42~58줄)을 아래 스니펫으로 교체
2. `npm test -- auth.spec.ts` 실행

다음: 테스트가 실패하면 첫 번째 실패 줄을 붙여넣어 주세요.
```

영어 출력이 필요한 경우:

```text
Run `npm install jsonwebtoken@latest`, then edit `src/auth.ts:42`.

1. Replace `verifyToken` (lines 42-58) with the snippet below
2. Run `npm test -- auth.spec.ts`

Next: paste the first failing line if a test fails.
```

## 품질 게이트

- [ ] 여덟 개 게이트 항목을 모두 통과했거나, 실패가 명시된 가드 예외다.
- [ ] 재작성 패스를 최대 1회만 실행했다.
- [ ] 두 표의 금지 표현이 하나도 남지 않았다.
- [ ] 첫 줄·마지막 줄 테스트가 두 질문에 모두 답한다.
- [ ] 재작성 과정에서 근거 없는 주장이 추가되지 않았다.
